# LUMINA CYBER SOLUTION v1.0 — KNOWN LIMITATIONS
**Product:** Lumina Cyber Solution  
**Release Version:** 1.0.0  
**Status:** Canonical Release Limitations Document  

---

## 1. Overview
In accordance with the Phase 16 Absolute Honesty and Release Verification rules, this document enumerates the documented limitations of Lumina Cyber Solution v1.0.0. These limitations represent intentional architectural boundaries and domain realities rather than software defects.

---

## 2. Preserved Documented Limitations

### Limitation 1: Workstation Lock Screen (Preserved from Phase 15)
> **Specification:**  
> *"Application-level workstation lock screen is provided. Complete Windows desktop lockout requires Windows Kiosk Mode or a companion background service."*
- **Operational Reality:** Lumina Cyber Solution displays an inescapable fullscreen web lock screen on client workstations when unassigned or locked by the cashier. However, standard web browser sessions running on Windows OS cannot intercept low-level hardware keyboard interrupts (such as `Ctrl + Alt + Del` or the Windows Key) without native kernel/service level companion software.
- **Recommended Operator Solution:** Deploy client PCs utilizing Windows 10/11 Assigned Access (Kiosk Mode) or apply Group Policy (`gpedit.msc`) restrictions to disable task switching for guest accounts.

---

### Limitation 2: Physical Paper Output Telemetry (Preserved from Phase 15)
> **Specification:**  
> *"Print command generation and driver dispatch are verified. Physical paper output requires human operator observation."*
- **Operational Reality:** The printing engine generates byte-perfect ESC/POS streams and confirms acceptance by the local operating system print spooler API (`DRIVER ACCEPTED`). Standard desktop and thermal receipt printers do not communicate physical paper feed completion back to the print spooler.
- **Recommended Operator Solution:** Cyber café counter staff must visually observe that receipt or document pages have physically printed before handing them to customers.

---

### Limitation 3: Offline Multi-Counter Conflict Resolution (Preserved from Phase 15)
> **Specification:**  
> *"Concurrent offline multi-counter terminal edits resolve via Last-Write-Wins."*
- **Operational Reality:** If two counter terminals become disconnected from the local network and simultaneously modify the identical customer ledger balance or profile record while offline, the synchronization engine applies Last-Write-Wins (LWW) based on terminal clock timestamp upon reconnection.
- **Recommended Operator Solution:** Assign primary cashier responsibilities for customer ledger credit updates to a single terminal during local network outages.

---

### Limitation 4: Payment Gateway Integration
> **Specification:**  
> *"Payment gateway integration not included in v1.0."*
- **Operational Reality:** Version 1.0.0 does not include online payment gateway API integrations (e.g. Stripe, Razorpay, or PayU webhook handlers). Counter transactions are recorded via Cash, Countertop Static/Dynamic UPI QR Codes (with manual cashier UTR/reference number logging), or Customer Account Balances.
- **Recommended Operator Solution:** Utilize printed UPI QR displays or POS card terminals; record the payment method and reference ID in the Lumina POS checkout interface.

---

### Limitation 5: Pilot & Field Validation Status (Preserved from Phase 15)
> **Specification:**  
> *"Phase 15 simulated pilot validation was completed. Live customer field deployment must be represented honestly until actual customer evidence exists."*
- **Operational Reality:** Lumina Cyber Solution v1.0.0 has passed comprehensive automated simulated pilot testing (276/276 tests across multi-counter shifts, stress loads, and fault injections). Initial commercial field rollouts should follow the Controlled Release guidelines in `V1.0-DEPLOYMENT-RUNBOOK.md`.
