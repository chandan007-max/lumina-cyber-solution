# LUMINA CYBER SOLUTION v1.0 — DEPLOYMENT RUNBOOK
**Product:** Lumina Cyber Solution v1.0.0  
**Target:** System Administrators, Commercial Deployment Engineers & Cyber Café Operators  
**Prerequisites:** Windows 10/11 x86-64 or Linux (Ubuntu 22.04+), Node.js v20.x LTS or higher  

---

## 1. System Requirements & Hardware Sizing

### Minimum Counter Host Sizing (1 Server / Primary Cashier PC)
- **Processor:** Intel Core i3 (4th Gen+) or AMD Ryzen 3
- **Memory (RAM):** 4 GB RAM (8 GB recommended)
- **Storage:** 500 MB free SSD storage for application and SQLite database
- **Network:** 100 Mbps / 1 Gbps Local Area Network (LAN) Ethernet or 5 GHz Wi-Fi
- **Operating System:** Windows 10/11 Pro (recommended) or Linux (Ubuntu Server/Desktop)

### Client Workstations (WS-01 through WS-20)
- Any desktop PC capable of running Google Chrome / Microsoft Edge in fullscreen mode.

## 2. Installation & First Setup

### Step 1: Environment Preparation
1. Install Node.js v20+ LTS from [nodejs.org](https://nodejs.org).
2. Clone or extract the Lumina release package to the target host:
   ```bash
   mkdir "C:\Lumina"
   cd "C:\Lumina"
   ```
3. Install production dependencies:
   ```bash
   npm ci --omit=dev
   ```

### Step 2: Environment Configuration
Create a production configuration file `.env` in the root directory:
```ini
NODE_ENV=production
PORT=3000
LUMINA_DB_PATH=./data/lumina.sqlite
ENCRYPTION_MASTER_KEY=your_64_char_hex_master_encryption_key_here
```
*(Generate a 64-character hex master key via `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`)*

### Step 3: Database & First-Run Initialization
Run the application service for the first time:
```bash
npm start
```
The migration engine will automatically construct the SQLite schema and enable WAL mode (`PRAGMA journal_mode = WAL`).

### Step 4: Initial Business & Owner Onboarding
1. Navigate counter browser to `http://localhost:3000` or host LAN IP `http://192.168.1.100:3000`.
2. Follow the First-Run Setup Wizard:
   - Enter **Cyber Café Legal Name**, Address, and Contact Numbers.
   - Enter **Primary Administrator / Owner Username & Secure Password**.
   - Select default currency (e.g. `INR (₹)`).
3. The wizard will create the primary tenant and configure root security policies.

---

## 3. Workstation & Hardware Setup

### Configuring Workstations
1. Navigate to **Admin Panel $\to$ Workstations**.
2. Click **Add Workstation**:
   - Identifier: `WS-01`
   - IP Address: `192.168.1.101`
   - Default Rate: `₹40.00 / hour` (Minimum charge: `₹10.00`)
3. Repeat for all client terminals.
4. On each client workstation, open Chrome in kiosk mode pointing to the client portal:
   ```bash
   chrome.exe --kiosk http://192.168.1.100:3000/client?ws=WS-01
   ```

### Configuring Receipt Printers
1. Navigate to **Admin Panel $\to$ Hardware Settings**.
2. Select Printer Type: `Thermal 80mm ESC/POS` (or `58mm ESC/POS`).
3. Set spooler destination (e.g., local Windows printer share name `POS-80`).
4. Click **Print Test Receipt** to verify driver communication.

## 4. Commercial License Activation
1. Obtain signed license token file (`license.jwt` or token string) from the Lumina License Authority.
2. Navigate to **Admin Panel $\to$ License**.
3. Paste token string or upload file and click **Activate License**.
4. The system validates the asymmetric signature using the embedded public key and immediately enables the corresponding terminal quota.

## 5. Routine Operations & Backup Schedule

### Hot Database Backup (Execute Daily or at Shift End)
Execute the SQLite checkpoint and backup command:
```powershell
# Windows PowerShell Daily Backup Script
$Date = Get-Date -Format "yyyyMMdd-HHmmss"
$BackupFile = "C:\Lumina\backups\lumina_backup_$Date.sqlite"
New-Item -ItemType Directory -Force -Path "C:\Lumina\backups"
node -e "const Database = require('better-sqlite3'); const db = new Database('./data/lumina.sqlite'); db.pragma('wal_checkpoint(TRUNCATE)'); db.backup('$BackupFile').then(() => console.log('Backup Complete')).catch(e => console.error(e));"
```

## 6. Update Procedure
1. Create a pre-update database backup:
   ```bash
   cp data/lumina.sqlite data/lumina_pre_update.sqlite
   ```
2. Stop the application service.
3. Replace application files with the new release version.
4. Run `npm ci --omit=dev`.
5. Start application service (`npm start`). Database migrations will apply automatically in an atomic transaction.
6. Check health endpoint `http://localhost:3000/api/diagnostics/health`.

---

## 7. Rollback Procedure
If an update encounters critical issues:
1. Stop the application service immediately.
2. Restore database: `cp data/lumina_pre_update.sqlite data/lumina.sqlite`.
3. Restore previous application binary release folder.
4. Restart application service.
5. Confirm operational status.
