## 1. Diagnostics Collection & Privacy Protection

When collecting diagnostic reports from customer cyber cafés:
1. Navigate to **Admin Panel $\to$ Diagnostics & Health**.
2. Click **Export Support Bundle**.
3. **Secret Redaction Policy:** The support bundle automatically redacts:
   - All passwords, bcrypt hashes, and salts.
   - Master encryption keys (`ENCRYPTION_MASTER_KEY`).
   - Plaintext SMTP passwords and SMS gateway tokens.
   - Unencrypted customer credit balances or government ID numbers.
4. **Never** instruct cyber café operators to email or paste their `.env` file or SQLite database raw files over unencrypted channels.

## 2. Common Operational Issues & Remediation

### Issue 1: "Workstation terminal displays 'Database Locked' or slow responses"
- **Root Cause:** A secondary process opened the SQLite database without WAL mode, or a long-running external backup stalled write transactions beyond the 5,000ms busy timeout.
- **Remediation:**
  1. Verify WAL mode: Run `node -e "const db = require('better-sqlite3')('./data/lumina.sqlite'); console.log(db.pragma('journal_mode'));"` $\implies$ Output must be `wal`.
  2. If output is `delete`, re-enable WAL mode: `db.pragma('journal_mode = WAL');`.
  3. Ensure no external utility (e.g. antivirus scanning lock) holds an exclusive file lock on `lumina.sqlite-wal`.

---

### Issue 2: "Receipt printer does not print or prints garbled characters"
- **Root Cause:** Incorrect baud rate / interface mode, or printer out of paper / cover open.
- **Remediation:**
  1. Inspect physical printer status (paper roll loaded correctly, feed button works).
  2. Verify configured printer type: `Thermal 80mm ESC/POS` vs `58mm ESC/POS`.
  3. Ensure Windows printer spooler service is running (`net start spooler`).
  4. Submit test print from **Admin $\to$ Hardware $\to$ Print Test Receipt**.

---

### Issue 3: "License shows 'Invalid Signature' after server migration"
- **Root Cause:** Server clock drift beyond allowable tolerance, or corrupted license string copy-pasted into interface.
- **Remediation:**
  1. Synchronize host server system clock via NTP (`w32tm /resync` on Windows).
  2. Re-download license token from customer portal and re-import via **Admin $\to$ License $\to$ Activate**.
  3. Verify token has not expired.

---

### Issue 4: "Terminal counter offline queue not syncing upon network reconnect"
- **Root Cause:** Local workstation clock drift or network firewall blocking WebSocket / HTTP POST requests to counter server.
- **Remediation:**
  1. Confirm client PC can ping the counter server IP (`ping 192.168.1.100`).
  2. In the cashier browser, open **POS $\to$ Offline Status**.
  3. Click **Force Sync Outbox**. Inspect network tab for HTTP 401 (expired session); re-login if cashier token expired during outage.

---

### Issue 5: "Workstation session timer did not stop when customer left"
- **Root Cause:** Cashier forgot to end session in POS terminal, or customer shut down client PC without cashier checkout.
- **Remediation:**
  1. Cashier opens **Workstations $\to$ WS-XX**.
  2. Click **End Session & Generate Bill**.
  3. If billable time accrued after customer departed, cashier adjusts line item or applies an authorized manager discount before finalizing payment.

## 3. Support Escalation Matrix

| Severity Level | Customer Impact | Target Initial Response | Escalation Path |
|---|---|---|---|
| **Tier 1 (Low)** | How-to questions, receipt layout customization, minor UI queries | < 4 Business Hours | Field Support Specialist |
